Ein­heit 1

Imperative und deklarative Entwicklung

Imperativ = wie (Schritt‑für‑Schritt‑Kontrolle, mehr Code, flexible Logik). Deklarativ = was (Ergebnis ausdrücken, einfacher, weniger Kontrolle). Power Apps unterstützt beides; dieses Modul fokussiert die imperativen Bausteine über Variablen.

🔡 Ein­heit 2

Die drei Typen von Variablen in Power Apps

  • Global: überall in der App gültig, Set(Name, Wert).
  • Kontext: nur auf dem aktuellen Bildschirm, UpdateContext({Name: Wert}).
  • Sammlung: Tabelle (Datensätze/Spalten), Collect / ClearCollect.

Variablen sind temporär (pro Benutzer/Session). Für Persistenz: in eine Datenquelle schreiben.

🌍 Ein­heit 3

Globale Variablen (Set)

Personalisierung ohne wiederholte Netzaufrufe

// Beim App‑Start speichern Set(varUserDisplayName, User().FullName) // Später nutzen "Welcome " & varUserDisplayName

Komplexe Ausdrücke einmal berechnen

// Auf Bildschirm sichtbar: Status vorab berechnen Set(varOutstandingExceeded, CountRows(Filter(InvoiceEntity, CustomerNumber = ThisCustomersNumber && Status = "Outstanding")) > 3) // Sichtbarkeit binden: // Icon.Visible = varOutstandingExceeded; Button.Visible = varOutstandingExceeded

🧩 Ein­heit 4

Kontextvariablen (UpdateContext)

Ideal zum Steuern von Popup‑Dialogen o. Ä. auf einem Bildschirm – Wiederverwendung auf mehreren Bildschirmen mit identischem Namen, aber ohne gegenseitige Beeinflussung.

// Popup anzeigen UpdateContext({ varShowPopUp: true }) // Mehrere auf einmal UpdateContext({ varCount: 1, varActive: true, varName: User().FullName })

Standardwahl oft: global. Kontextvariablen sind großartig für isolierte Bildschirm‑Logik.

Referenz: Einheit 4 – Kontextvariablen

📦 Ein­heit 5

Sammlungen (Collect/ClearCollect)

Leistungsoptimierung durch Caching

// Tabelle einmal laden und mehrfach nutzen Collect(collectProjects, Projects)
  • Nicht delegierbar: Collect lädt standardmäßig nur die ersten ~500 Datensätze.
  • Entkoppelt von der Quelle – Änderungen in der Sammlung werden nicht automatisch zurückgeschrieben.
  • Temporär – beim Schließen der App werden Inhalte verworfen.

Dynamische Sammlungen

Collect(collectColors, {Name:"Shane", FavoriteColor:"Orange"}, {Name:"Mary", FavoriteColor:"Blue"}, {Name:"Oscar", FavoriteColor:"Yellow"})

🧠 Ein­heit 6

Weitere Variablenkonzepte

  • Selbst‑Referenz: Zähler/Anfügen, z. B. Set(varCounter, varCounter + 1).
  • Datensatz in Variablen: Set(varUser, User()) und Zugriff via varUser.Email.
  • Standardwerte: Text = "", Zahl = 0, Boolesch = false.
  • Kein Auto‑Refresh: Variablen aktualisieren sich nur durch Ihre Logik oder beim Neustart.

🧪 Praxis

Übung – Variablen und Sammlungen verwenden

  1. Neue Canvas‑App (Tablet) anlegen; in App.OnStart ClearCollect(colCustomer,…) + Set(varUserDisplayName, User().FullName).
  2. Galerie anlegen, Items = colCustomer, Papierkorb‑Icon pro Eintrag.
  3. OnSelect Papierkorb: erst UpdateContext({varPopup:true}); Popup (Rect/Label/Buttons) gestalten.
  4. Bestätigen: Remove(colCustomer, ThisItem); Abbrechen: UpdateContext({varPopup:false}).

🧾 Ein­heit 9

Zusammenfassung & Extra‑Tipps

  • Power Apps vereint imperativ & deklarativ – Variablen sind der Schlüssel für imperative Logik.
  • Global für appweite Zustände; Kontext für Bildschirme; Sammlung für tabellarische Daten.
  • Denk an Delegation & Persistenz (Schreiben in Datenquelle) für Performance & Datenhaltbarkeit.
